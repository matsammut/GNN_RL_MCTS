# Job Shop Scheduling with Reinforcement Learning and Evolutionary Optimisation

This repository contains implementations and experiment scripts for investigating learning-based and evolutionary approaches to the **Job Shop Scheduling Problem (JSSP)**. The project compares online reinforcement learning, evolutionary optimisation, behaviour cloning, and offline reinforcement learning using Taillard benchmark instances.

## Research objectives

1. **Experiment 1 — PPO and evolutionary optimisation:** compare Proximal Policy Optimisation (PPO) with a Genetic Algorithm (GA), Memetic Algorithm (MA), and Hybrid Genetic Algorithm (HGA), considering schedule quality and computational time.
2. **Experiment 2 — offline learning from generated demonstrations:** use synthetically generated demonstrations to train and evaluate Behaviour Cloning (BC) and Conservative Q-Learning (CQL) policies.

The implementations are intended for research and experimental comparison. Results depend on the selected instances, configuration, compute environment, and stopping criteria.

## Methods at a glance

- **PPO — Proximal Policy Optimisation:** an online reinforcement learning approach used in Experiment 1.
- **GA — Genetic Algorithm:** an evolutionary optimisation baseline.
- **MA — Memetic Algorithm:** a genetic algorithm augmented with local search.
- **HGA — Hybrid Genetic Algorithm:** a hybrid evolutionary approach incorporating local search.
- **BC — Behaviour Cloning:** supervised learning from state–action demonstrations generated by an optimisation procedure.
- **CQL — Conservative Q-Learning:** an offline reinforcement learning method trained from a fixed dataset of transitions.

## Data and evaluation

- **Benchmark instances:** `PPO/instances/`
- **Best-known solutions:** `PPO/bks.json`
- **Experiment 1 results:** `PPO/ppo_vs_evolutionary_comparison.csv`
- **Generated results and checkpoints:** `PPO/checkpoint_results/`, `PPO/ga_results/`, `PPO/ray_results/`, and `PPO/tabulated_results/`

The principal schedule-quality measure is the makespan, \(C_{\max}\). Where BKS values are available, the percentage gap is:

\[
\operatorname{BKS\ Gap}(\%) =
\frac{C_{\max} - \operatorname{BKS}}{\operatorname{BKS}} \times 100.
\]

A lower makespan or BKS gap indicates a better schedule. A BKS is a best-known value and does not necessarily represent a proven optimum.
